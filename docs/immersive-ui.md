# 自由視点への没入UI

通常動画は画面いっぱいに表示し、中央には再生ボタンを置かない。再生・停止は左下または映像の短いタップ、声援と共有は右側、タイトル・競技・出典は下部にまとめる。コメントとタグは「概要」から開く。検索・アカウント・共有リンクの経路を維持する。

## 切り替えの契約

- 中央の領域を280ms長押しして初めて演出を開始する。以降1200msで炎を下から充填する。短いタップ、充填前の指離し、24pxを超える移動は入場を成立させない。
- 長押し成立時に通常動画の時刻と再生状態を保存して静止し、実際の自由視点シーンを読み込む。準備中も中央の通常動画は保持する。明示的な「自由視点で見る」は長押しが難しい利用者の代替で、充填操作を省略する。このボタン自体を長押しした場合も指を離さず起動できる。
- 充填完了とシーンの初回描画・シーク完了の両方を待ち、指を離す操作を条件にせず自動で入場する。充填後は押し続けても離してもよい。待ち時間のタイマーで準備成功を偽装しない。フレーム時刻の丸めは既存viewer adapterに従う。
- 開眼と軌道線を同じアニメーション時刻から開始する。開眼は240ms、軌道線の立ち上がりは550ms。開眼後の姿を2200msまで保ち、最後の650msで演出だけを薄くする（合計2850ms）。映像の拡大率は1.75倍を維持し、自由視点の表示にも同じ拡大率を引き継ぐ。最後にズームを戻したり、自由視点側のカメラを自動で動かしたりしない。共有URLから直接自由視点を開く場合は入場ズームを適用しない。
- 充填中は通常動画だけを1→1.75倍へ拡大する。押し続けるほど加速して近づき、開眼後の姿を保つ間は拡大率を維持する。引く予備動作や入場後の自動カメラ移動を追加しない。画面全体の火の粉と赤い光、元の炎形状の揺れを使う。
- 通常動画へ戻る操作は演出を入れず、自由視点の時刻へ通常動画をシークする。通常動画とシーンは戻れる間だけ保持し、カード破棄時に解放する。
- 準備中と自由視点中はフィードのスワイプ・上下ボタン・上下キーで動画を切り替えない。中央のドラッグは自由視点の操作に渡す。準備キャンセルまたは通常動画への復帰で解除する。
- PCのホイール／トラックパッドは1回の連続したスクロール操作で1本だけ切り替え、380msの滑らかなスライドで移動する。慣性入力で途中停止・連続ジャンプさせず、240ms入力が途切れ、移動も完了してから次の操作を受け付ける。指の縦スワイプは既存のページ送りを維持する。
- OSのアニメーション抑制設定では火の粉・揺れ・ズーム・開眼演出を省き、実描画の準備完了を待って切り替える。振動は対応環境だけで実行し、未対応でも視聴を妨げない。

## 画面の移動

フィードにはLIVE・検索・アカウントの入口を置く。管理者でログインすると管理ページへ移り、GS生成とLIVEを管理する。`/demo/?generate=1` も管理者専用とする。中央の長押し説明文は表示せず、長押しと「自由視点で見る」の操作を維持する。

LIVEのヘッダーは高さ64pxと上部の安全領域を確保し、3Dビューと重ならない位置へ置く。フィードやLIVEの直リンクから開いた場合は「フィードに戻る」、生成画面から開いた場合は「生成に戻る」と明記する。準備中・取得失敗時も同じ戻る領域を使う。widgetでは既存のコールバック不良は再現しておらず、実ブラウザの履歴・iframe操作は手動確認の対象とする。

## ロゴ

`apps/web/assets/brand/rangle-editable.svg` は提供された原本。21個のpathを `brand_art.dart` のFlutter Canvasへ変換し、文字・炎・目・軌道線の輪郭を維持する。塗りの方向はFlutterのグラデーションとして設定する。SVGをそのまま回転・拡大するのではなく、開眼部分と軌道線を別々に描画する。

```bash
python apps/web/tool/generate_brand_art.py
dart format apps/web/lib/widgets/brand_art.dart
```

生成元を変更した場合は生成後に `flutter analyze` を確認する。

## 声援と熱量バー

声援はいいねのオン／オフと別データで、ログイン後に複数回送信できる。1本の映像を48区間に分け、押した再生位置の件数を加算する。シークバーのオレンジの濃さは区間内件数の相対値で、0件を人気として着色しない。

声援を受け付けた直後、ボタンの近くに10粒の小さな火の粉を舞わせ、約850msで消す。上昇は約50px以内、連打は最大4回分まで重ね、完了後は描画更新を止める。火の粉は入力を受け取らず、動画や共有操作を遮らない。OSのアニメーション抑制設定では省略する。初回の集計読み込みや他ユーザーの件数増加では発火しない。

GETは匿名でも可能。POSTは既存のセッション・変更要求の保護・ユーザー単位の頻度制限を使う。

| API | データ |
| --- | --- |
| `GET /api/v1/clips/{id}/cheers` | `{ "bins": [48個の非負整数] }` |
| `POST /api/v1/clips/{id}/cheers` | `{ "request_id": "32桁の小文字hex", "bins": [48個の非負整数] }` |

POSTの合計は1〜64件、負数・余分な項目・異なる区間数は拒否する。フロントは約2秒でまとめて送信し、失敗時は同じIDと内容で再送する。送信中の追加タップは次のバッチへ分ける。表示件数は未送信分を含み、失敗時は詳細から再送できる。古いGET応答が新しい送信済み件数を戻さない。

Firestoreは既存named DBの `clips/{id}/cheer_shards/{00..31}` に区間数を分散保存し、`cheer_receipts/{ユーザーIDとrequest_idのhash}` を同一transactionで作る。再送は加算しない。同じIDで内容を変えると409になる。1回の集計取得は最大32document。rawユーザーIDや各タップの時刻は公開応答に含めない。

この変更はDBやIAMを作成・適用しない。既存のcommunity保存先が有効な環境へGoとFlutterを一緒に反映する。receiptには7日後の `expires_at` を記録するが、**cheer_receiptsのTTL設定はまだ追加していないため自動削除されない**。保持期間とTTLはインフラ担当と決める。削除後の古いrequest_idまで永久に重複排除する契約ではない。

他の利用者の件数はカード有効化時・自分の送信応答で更新する。リアルタイムの同時声援配信は未実装。ブラウザ終了・ログアウト・通信失敗後のカード破棄では未送信分を保証しない。通常のカード破棄では送信待ちを可能な範囲で送って終了し、ログアウト時は別ユーザーへ未送信バッチを引き継がない。負荷・費用・分散した不正連打への対策は大規模配信前に別途検証する。

## ローカル検証記録

以下は導入時の検証記録。現在のナビゲーションは[画面の移動](#画面の移動)を参照。

### LIVEと生成画面の統合

`origin/stg` の `767a1d7`（PR #98）まで取り込んだ。LIVE index・クラウドLIVEジョブ・viewer更新・開始／停止UIに加え、LIVE公開のバックプレッシャー対策、デコード用CPU容量、動画と自由視点の再生引き継ぎの更新を含む。`PreviewViewer` と `ClipCard` の競合は、source更新・SHA照合・再試行と、再生controller・没入演出の両方を保持して解消した。

動画のネイティブ時刻をcaptureし、宣言されたpreview/sceneの対応情報とフレーム間隔で変換する。sceneのrestore完了を待って開眼し、復帰時も動画のrestore完了まで自由視点を残す。対応情報がないsceneは0秒で停止し、元の動画時刻と再生意図を保持する。末尾を超える場合は最終sampleへ合わせ、小さく調整時刻を表示する。準備中の動画操作を維持する旧UIとは異なり、没入演出中は動画を静止し、切り替え開始時の時刻と再生意図を固定する。再生引き継ぎのテストはこの契約と、動画を再作成せず保持する設計に合わせて更新した。キャンセル・再試行・revision変更後の古い完了通知が復活しないことも検証する。

- フィード上部のLIVE入口から一覧・視聴へ進める。小画面では件数をロゴの下へ移し、ロゴの幅を確保する。
- LIVEと生成に共通のRANGLEヘッダーを使い、黒・暖色のパネル・オレンジの操作色を統一する。LIVEの映像はヘッダーの背後まで表示し、情報は下部へ寄せる。
- LIVEは左下の再生／一時停止と下部の状態表示にまとめ、録画用のシークバーを表示しない。モデル更新時の視点保持、古いモデルへの後退防止、失敗時の表示保持と再接続は元の処理を維持する。
- 生成画面には静的・動的・LIVEのプリセット、LIVE開始、ジョブの状態、LIVE視聴、停止確認を残す。所有者の停止操作は映像の準備中も下部に表示する。
- LIVEヘッダーの入力保護は高さ64pxに限定し、中央の視点操作を覆わない。出典ダイアログは既存のiframe入力保護付き経路を使う。

320×640、390×844、844×390、1440×900で、一覧→視聴→一時停止／再生→出典→復帰、生成→LIVE開始→視聴→停止を入力テストとFlutter描画で確認した。2倍文字での既存生成テストも実行する。PNGはローカルの検証用で、映像面はFakeViewerである。

ローカルプレビューのAPIは作業ディレクトリの確認専用サーバーで、合成RGS1モデル・一時ジョブ・プレビュー用ユーザーを使う。本物のDart API clientでプリセット、同一IDの開始再送、状態取得、LIVE取得、停止を確認し、JS viewer parserでmanifest・モデルSHA256・temporal primitiveを検証した。クラウドGPU起動・実中継・実撮影遅延の確認ではない。実APIへ接続する通常ビルドの契約は維持し、GCPへの配備は行っていない。

2026-11-09、Flutter 3.47.9 / Dart 3.13.7。Flutterによる実描画と入力テストで390×844・1440×900を確認し、充填・開眼後・自由視点・即時復帰を検証した。320×640、844×390、2倍文字の既存テストでもモーダル・操作領域・シーンへの入力を確認する。描画テストの映像面はFakeViewerであり、実映像・WebGL・実端末の振動確認とは区別する。ローカルPNGは作業環境に保持し、コミットしない。

Flutterテスト186件、Linuxでの `go test -race ./...` と `go vet ./...`、Linuxでのviewerテスト50件が成功した。Goの検証後に取り込んだPR #98はWebのみを変更している。`flutter analyze` は指摘なし、release Webビルドも成功した。Windowsでの既存Go symlinkテストはOS権限不足、既存viewerテスト3件はfile URLからWindowsパスへの変換で失敗するため、同じソースをLinuxコンテナで検証した。今回のUI変更でそれらの既存テストを書き換えていない。

ブラウザ自動確認は、`/demo/` の配信pathを修正した後も画面取得がタイムアウトして未完了。実ブラウザでのHTML video/iframeの重なり、GPU上の初回描画、低速回線、タッチの体感と振動はレビュー前に確認する。Firestore実サービス／emulatorでの声援transactionも未検証。合成入力のテスト成功をクラウド運用・実機性能の成功とは扱わない。
