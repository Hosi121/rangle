# Gaussian再構成の画質と描画条件

2026-11-07のVRUローカル実験。初期点群の増加で撮影視点付近は改善したが、大きなorbitでの選手・コートの崩れは残った。別素材の[UVG-GS比較](gaussian-training.md)、現workerの[学習比較](../training-quality.md)とは条件が異なる。

## 比較条件

VRU Basketball gz、先頭20frame/25fps、30 train、4 held-out×20frame＝80画像。seed0、6000step、480×270評価を固定。LocalDyGS commit `39dacdcd8ef6d2b93824df79041713b4a29fb828`。供給点群・校正には評価camera情報が含まれ得るため、独立した未知視点への汎化比較ではない。

| 学習条件 | PSNR (dB) | SSIM | 判定 |
| --- | ---: | ---: | --- |
| 基準：480×270、初期anchor 24,833 | 29.115 | 0.9357 | 比較元 |
| hash/network容量を拡大 | 29.193 | 0.9372 | 費用に対し改善が小さく保留 |
| 480×270、初期anchor 99,328 | 30.158 | 0.9519 | 部分改善候補 |
| 上記＋時間変化領域のL1重み4倍 | 30.187 | 0.9523 | 選手ROI 6か所中5か所でPSNR低下、不採用 |
| 初期anchor 99,328、960×540入力 | 25.956 | 0.8991 | 固定480描画では不採用 |

点群増加は80/80画像でPSNRを改善したが、顔・脚のぼけと残像は残る。量子化alphaが0の点だけを除いたbytesは、20frame合計128,671,424→461,056,192、先頭6,190,976→22,334,656。転送量約3.58倍を伴う。モデル・実験コード・生ログは公開リポジトリに含めない。

## 学習と表示の解像度

同じ80画像をuint8 PNGで再評価した描画スケール診断。上表のfloat評価とは別集計。

| 学習入力 | 480×270で直接描画 | 960×540描画→480×270へLanczos縮小 |
| --- | ---: | ---: |
| 480×270 | 30.152 dB | 25.334 dB |
| 960×540 | 25.954 dB | 30.158 dB |

学習と異なる描画スケールでは両方向に劣化し、960学習による最終480画像の上積みは未確認。使用CUDA実装は投影共分散へ固定値0.3を加えるため、画素フィルタも比較条件に含む。

任意の`camera.referenceImageHeight`はdrawing bufferの高さを固定する。GaussianSplats3D 0.4.7のrenderer/Viewer/SplatMeshでpixel ratioをそろえ、resize・新meshにも引き継ぐ。未指定は従来動作。横幅・横画角は表示領域の縦横比に従い、480×270全体を固定する設定ではない。CSS拡縮は細部を増やさない。

## ビューアの確認

Windows Edge 156 / ローカルGPU（ANGLE D3D11）で、CSS480×270/DPR1と、基準高さ270のCSS960×540/DPR1、CSS480×270/DPR2、CSS960×540/DPR2を比較。同カメラ・時刻の480×270 RGBAは4条件でbyte一致し、resize・frame19のmesh差替後も一致した。

実資産のAPI→動画→自由視点→時刻変更→orbit→動画復帰を390×844/1440×900で確認し、JS/WebGLエラー0。これは描画・操作の確認で、再構成精度やスマートフォン実機の速度・メモリ測定ではない。

## 残る制約

配信`.splat`の再読込とexport前のCUDA描画にも大orbitで同様の崩れがあり、packingだけでは説明できない。撮影cameraはほぼ同一平面で、問題のorbitはその外側だった。原因は未特定で、撮影範囲内の補間と範囲外移動を分けて評価する。

当時は離散frame選択UIを使用。[連続再生](../temporal-playback.md)への移行後も、端末性能・初回表示・ABR・撮影範囲外の画質は別途検証が必要。
